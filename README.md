# logstats

一个小型日志延迟统计命令行工具，只用 Python 标准库。

```
python3 -m logstats.cli --file sample/app.log \
    --from 2026-09-22T00:00 --to 2026-09-22T02:00 \
    --window-minutes 60 --top 5
python3 -m unittest discover -s tests -v
```

可选参数：

- `--grace-minutes N`：乱序容忍的迟到时长（分钟），默认等于窗口长度。
- `--exact`：保留全部样本精确计算 P95，用于和默认的直方图估算对照
  （内存随记录数增长，仅建议在对照/调试时使用）。

## 日志格式

每行一条：

```
<ISO 时间戳> <LEVEL> [组件] handled in <毫秒>ms
```

例如：

```
2026-09-22T00:05:00 INFO [api] handled in 10ms
2026-09-22T09:10:00+08:00 INFO [db] handled in 5ms
```

空行忽略；格式不对的行不会中断统计，而是计入「解析失败」并在结尾列出。

## 统计口径

- **时间轴统一按 UTC**：日志行里带偏移的时间戳（`+08:00`、`Z`）先换算到 UTC，
  再和 `--from` / `--to` 比较；`--from` / `--to` 不带偏移时按 UTC 解释。
- **窗口是半开区间**：窗口 `[起点, 起点+窗口长度)`，一条记录只会落进一个窗口，
  相邻窗口的条数相加等于区间内的总条数。
- **百分位用最近秩（nearest-rank）**：对 `n` 个样本求 `p` 百分位，取排序后
  第 `ceil(n * p / 100)` 个（1 起数）；样本为空返回 `None`。

`--from` 含、`--to` 不含。

## 乱序与迟到

记录可以按任意顺序到达，统计始终按事件时间（UTC）归窗。分析器维护一条
**水位线**（已见记录的最大事件时间）：

- 事件时间早于 `水位线 - grace` 的记录视为迟到超限，计入「迟到丢弃」，
  不会落进任何窗口，也不参与组件汇总；
- grace 默认等于窗口长度，可用 `--grace-minutes` 调整；
- 不在 `--from` / `--to` 区间内的记录不算迟到，只计入「文件」总数。

因此始终有 `合计 + 迟到丢弃 = 区间内`。

## 直方图估算

默认模式不保留全部样本，每个组件的延迟用一个**固定桶数上限的等宽直方图**
（不超过 4096 个桶）估算：

- 桶宽从 1 毫秒开始；当值域跨度超过桶数上限时，桶宽翻倍、相邻桶两两合并，
  因此内存占用与记录数无关；
- P95/P99 估计取目标桶的**中点**；真实的最近秩百分位是该桶内的某个样本，
  故估计误差**不超过半个桶宽**，输出的「误差上界」即各组件半个桶宽的最大值；
- `--exact` 模式保留全部样本走精确的最近秩计算，两种模式的差一定落在
  声明的误差上界之内。

## 输出

```
窗口统计（窗口 60 分钟）
2026-09-22T00:00  10
2026-09-22T01:00  16
合计 26 条 / 区间内 26 条 / 文件 26 条
迟到丢弃 0 条
误差上界 ±0.5 ms

组件 P95（毫秒）
组件          条数     P95
api         20   190.5
db           6    25.5
```

加 `--exact` 后「误差上界」为 `±0 ms`，P95 为精确值（上例中 api 为 190、db 为 25）。
